**Band-index caveat.** The dissertation EPS filenames `no7` / `no9` are
misleading MATLAB save-script labels — they do *not* correspond to the
7th and 9th eigenvalues at those µ-points. Verified numerically against
`Diffusion2D(mesh_n=64, coefficient_3_3_2)`:

```
µ=0.775: no7=200.699 (matches diss λ=200.3),
         no8=223.752 (matches diss "no9" λ=223.23),
         no9=231.269 (unused by the dissertation)
µ=0.85:  no7=183.796 (matches diss λ=183.369),
         no8=200.210 (matches diss "no9" λ=199.786),
         no9=204.239 (unused by the dissertation)
```

So the dissertation prose `Π[7,7]..Π[8,8]` and the four EPS panels both
concern bands **7 and 8** (1-indexed), i.e. 0-indexed `(6, 7)`. The
emitted `crossing-eigenfunctions.png` renders bands `(6, 7)` accordingly.

## Error-table semantics

The CSV mirrors the dissertation's Table 1D Error:

| Column | Definition |
|---|---|
| `level` | Refinement iteration (0..terminal_level) |
| `n_points` | Number of grid nodes inserted by end of this level |
| `n_subintervals` | Number of edges active at this level (sorted adjacent pairs in 1D) |
| `n_wrong_match` | Nodes whose pipeline-propagated band identification disagrees with continuous truth-tracking. The pipeline propagates band labels from the level-0 midpoint through each edge's a-priori matching; truth labels come from continuous tracking of the dense `--truth-points` sweep. A node is "wrongly matched" iff its propagated label permutation differs from the truth permutation in at least one band. |
| `n_uncertified` | Edges at this level whose verdict tuple contains anything other than `Verdict.CERTIFIED` (i.e., `REFINE` or `CLUSTER`). |

**`n_wrong_match` semantic differs from the dissertation's column 3.** The
dissertation's column is an internal-consistency count produced by the
MATLAB pipeline (no continuous truth sweep). The rebuild's column compares
pipeline-propagated labels against an independent dense truth sweep — a
stricter test that the dissertation never ran. Expect the rebuild's
`n_wrong_match` to be ≥ the dissertation's value even when grid topology
matches exactly; that is a metric-definition difference, not a tuning
failure.

## Reproducing

```bash
uv run python scripts/reproduce_3_3_2.py                # --mode both (default)
uv run python scripts/reproduce_3_3_2.py --mode firstk  # legacy top-level layout
uv run python scripts/reproduce_3_3_2.py --mode window  # window/ subdir only
```

Useful flags: `--mode`, `--preset`, `--mesh-n`, `--n-eigs`, `--max-levels`,
`--truth-points`, `--out-dir`.

### Operating modes

The script renders the §3.3.2 problem under either the **FirstK** preset
(`RefinementConfig.dissertation_3_3_2_preset()` — `FirstK(n_eigs=6)`) or
the **Window** preset
(`RefinementConfig.dissertation_3_3_2_window_preset()` —
`Window(λ ∈ [0, 270], k_initial=15)`, anchored_absolute,
`t_pi=0.21`), or both.

- `--mode firstk` → writes the legacy artifact family to the top-level
  artifacts dir (`reference-spectrum.png`, `adaptive-grid.png`, `grid-level-1..4.png`,
  `projection-matrix-1..4.png`, `crossing-eigenfunctions.png`,
  `subinterval-matching.png`, `surrogate-level-1..4.png`, `error_table.csv`,
  `verdict-map.png`).
- `--mode window` → writes to `window/` (same family; its
  `error_table.csv` drops the FirstK-tied `n_wrong_match` column — see
  `window/README.md`). Adds `verdict-map.png` and the window-shaded
  `reference-spectrum.png`.
- `--mode both` (default) → emits FirstK to top-level *and* mirrors the
  FirstK artifacts into `firstk/` for the Quarto book's side-by-side
  layout; emits Window to `window/`.

### Presets

- **`--preset dissertation_3_3_2`** (default for `--mode firstk`) — applies
  `RefinementConfig.dissertation_3_3_2_preset()` (`t_pi=0.21,
  t_lambda=0.001, n_eigs=6, max_levels=8`, the dissertation's stated 1-D
  tolerances). This terminates at level 3 with `ran_out=False` but on a
  **13-node** grid — it does *not* reproduce the published 8-node Table 1D
  Error grid. That grid was a tuning artifact of the retired `t_pi=0.35`
  (see the preset-provenance audit); the faithful reproduction is the
  window-mode preset, since the dissertation's 1-D example was
  computed in window mode, not FirstK.
- **`--preset none`** — use library defaults (`t_pi=0.21` relative,
  `t_lambda=1e-3`, `n_eigs` from CLI). Reproduces the un-tuned divergence
  (grid blows up to ≥ 16 nodes, cap hit). Useful for measuring the cost
  of the rebuild's stricter generic defaults vs the dissertation preset.

`--preset` only governs the FirstK run; the Window run always uses
`dissertation_3_3_2_window_preset()` (`I_λ = [0, 270]`). Window
mode is the **faithful** reproduction of the dissertation's published 1-D
Table 1D Error grid — it terminates at L=3 on an **8-node** grid
(3→5→7→8), whereas FirstK with the same `t_pi=0.21` terminates at L=3 but
on a **13-node** grid (its fixed 6-band cutoff over-refines at the
band-7/8 near-degeneracy). The two modes share the termination *level*,
not the grid.

The comparison is qualitative — match shape, ordering, and crossing
locations against the EPS, not pixel-identity. The dissertation uses
a finer reference mesh than the script's default `mesh_n=64`.
