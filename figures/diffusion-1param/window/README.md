# §3.3.2 1D example — Window-mode reproduction

Generated by `scripts/reproduce_3_3_2.py --mode window`. The PNGs are
not tracked in git; re-run the script to regenerate them.

## Mode

`RefinementConfig.dissertation_3_3_2_window_preset()`:
`Window(lambda_lo=0.0, lambda_hi=270.0, k_initial=15)` with
`max_levels=8`, `pruning_mode="anchored_absolute"`, `projection=False`,
`t_pi=0.21`, `t_lambda=0.085`. This is the dissertation's published λ-window
`I_λ = [0, 270]` (`Chapter_3.tex:368`), verified by the band counts at
`Chapter_3.tex:370` (four bands at µ=0.4, nine at µ=0.7). It **reproduces
the §3.3.2 L=0..L=3 grids exactly** and terminates at L=3 with
`ran_out=False` — the same termination level as FirstK, so the two modes'
grid evolutions can be compared on equal footing. Every interior unmatched
band is gated by the DIR-031 Algorithm-6 `t_c` row-norm test (so the
`ENTERED`/`EXITED` labels are diagnostic only, never `REFINE`-equivalent).
It terminates on an **8-node** grid (3→5→7→8), the published Table 1D
Error progression — *not* the same grid as FirstK's 13 nodes.

## `error_table.csv` (window schema)

The window table drops the FirstK-only `n_wrong_match` column: that
column compares each node's propagated band labels against a *fixed-band*
continuous-truth sweep, but window-mode snapshots are ragged — each
parameter point keeps whatever eigenpairs fall inside
`[lambda_lo, lambda_hi]` (four bands at µ=0.4, nine at µ=0.7) — so there
is no fixed band index to compare against. The remaining columns
(`level, n_points, n_subintervals, n_uncertified`) are mode-agnostic and
reproduce the dissertation's published Table 1D Error grid: `n_points`
runs 3→5→7→8 and `n_uncertified` (REFINE-flagged subintervals) runs
2→2→1→0, certified at L=3.

**`verdict-map.png` complements the table**: each colored
edge segment shows the majority verdict across that edge's per-band
verdict tuple. Blue (`ENTERED`) and purple (`EXITED`) segments are the
window-mode-specific signal that a band crosses the
`[lambda_lo, lambda_hi]` boundary between adjacent grid points.

## NExact shading

`reference-spectrum.png` shades the `[0, 270]` λ-band in grey. Since the published
window spans essentially the whole low spectrum (all four bands at µ=0.4
and nine at µ=0.7 fall inside it), the shaded band is broad by design —
it marks the eigenpairs the ragged window keeps, not a narrow crossing
strip.

## NExact reference spectrum

`reference-spectrum.png` (Window mode) is solved **directly on the window
`[0, 400]`** — each µ-point runs a ragged window solve returning exactly the
in-window eigenpairs, so nothing above 400 is computed and nothing is clipped.
It is drawn in **eigenvalue order**: the parameter is 1-D, so crossings are
generically *avoided* (a true crossing needs two free parameters), the branches
never swap eigenvalue order, and the k-th smallest eigenvalue at every µ is one
smooth line. The grey strip is the algorithm's kept window `[0, 270]`; the sweep
window runs higher so bands descending into the kept window are visible entering
from above. The band-7/8 avoided crossing near µ≈0.81 shows as two curves
approaching to the minimum gap (≈13.7) and separating.

## NLevel surrogates

`plot_level_surrogate` reconstructs surrogate bands from the greedy grid's
**own stored matchings** (`edge.matching.pairs`) via `propagate_band_labels` —
never re-matched. Labels are propagated once over the full final graph from a
fixed root, so each branch keeps one colour/slot across every level; branch `k`
of the surrogate follows branch `k` of the grey reference *through* a crossing.

Window-mode snapshots have ragged `k`: a band outside `[0, 270]` at a node is an
honest `NaN` gap in its *fixed* slot (one colour, a broken curve), never a
recoloured connector to an unrelated branch. A band that leaves and re-enters
the window keeps its slot/colour with the gap between.
